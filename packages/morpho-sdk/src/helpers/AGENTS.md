# `helpers/`

Pure protocol-specific utilities shared across layers. They never mutate inputs; fresh return objects are required only when explicitly promised by the function's JSDoc. Returning an input unchanged is otherwise valid. Inherits [`packages/morpho-sdk/AGENTS.md`](../../AGENTS.md).

Per-function contracts (arguments, return shapes, behavior) live as JSDoc on each function — that's the canonical source. This file documents only the layer-level invariants and the shape of the helper categories.

## Categories

- **Validated input contracts** — internal, non-barrel `parse.ts` owns the `BlueMarket` contract: a frozen plain tuple/id snapshot, never the caller's instance. Its scalar guards return ordinary values and are details of operation-specific whole-params constructors, not separate witnesses that callers assemble. Blue operation constructors own their complete readonly contracts, including mode, cap, fee coverage, funding and allocation constraints. They do not prove chain state or future signature validity. Deadline shape checks are clock-free; entities recheck expiry in `getRequirements()`.
  Midnight whole-params constructors similarly own market tuples, configured collateral indexes,
  amounts, addresses and partial native funding. `parseMidnight.ts` supplies ordinary scalar guards
  and the shared owned market contract, not independent field witnesses for entity bodies to assemble.
  These contracts do not prove balances, position health, oracle state or authorization.
- **Encoders** (ABI encoding plus input validation, no I/O) — internal, non-barrel helper `encodeForceDeallocateCall(deallocation, onBehalf)` (consumed by `actions/vaultV2/forceRedeem.ts`). ABI-encodes a single `VaultV2.forceDeallocate` calldata entry and throws `NonPositiveInputError` on a non-positive `amount`. The `data` field carries ABI-encoded `MarketParams` for the Morpho Market V1 adapter, or empty bytes otherwise. `getMidnightBlueBuyCallbackData(blueMarket)` ABI-encodes the Blue market as the `callbackData` of `supplyBlueMakeLend` offers. Internal sub-helpers (e.g. `encodeDeallocateData`) are not exported.
- **Midnight callback derivation** — `getMidnightBlueBuyCallbackAddress({ chainId, owner, salt })` is a wrapper that delegates to midnight-sdk's `getBlueBuyCallbackAddress`, which computes the maker's `BlueBuyCallback` CREATE2 address offline from the registry's factory, `midnight`, and `blue` addresses. The pinned callback creation bytecode lives in `packages/midnight-sdk/src/callbacks/BlueBuyCallback.ts` and must be updated there if the factory is redeployed.
- **Validators** (pure, throw typed errors) — `validateSlippageTolerance(...)`, `validatePositionHealth(...)`, `getMidnightMaxSafeDebt(...)`, and the internal, non-barrel `validateVaultV2BlueReallocations(...)` (consumed by `actions/blue/common.ts`). Each enforces a public-API invariant: see the `error.ts` exports for the full list of error classes a caller may pattern-match on. Guards that more than one periphery shares live here as `@internal` non-barrel exports rather than per-call-site copies: `validateUint256Field(field, value)` for the ABI bound, `validateDeadline(deadline)` for the positive-`uint256` deadline every periphery requires (clock-free, so transaction builders can call it; callers needing freshness layer their own `ExpiredDeadlineError`), and `validateReferralFee({ referralFeePct, referralFeeRecipient })`, which returns the normalized pair the fixed-bundle peripheries (BlueBundlesV1, VaultBundlesV1, VaultExitBundlesV1) encode. Midnight-specific `@internal` guards live in `validateMidnightBounds.ts`: `validateMidnightUint128Field(field, value)` for amounts, units and caps Midnight stores as `uint128`, `validateMidnightCollateralSupplySums(field, supplies)` for per-collateral-index sums, `validateMidnightTakeableOfferBounds(...)` for taken offers' `uint128` caps, `validateMidnightTakeableOfferFields(...)` (in `validateMidnightTakeableOfferFields.ts`) for the remaining ABI-encoded fields of taken offer fills, called by every TransactionPlan take preparer right after the action parse constructor, and `validateMidnightReferralFeeCap(referralFeePct)` for the SDK's referral-fee cap. Midnight take-feasibility `@internal` guards live in `validateMidnightTakeFeasibility.ts`: `validateMidnightSellTargetBounds(...)`, called by the three raw sell builders, and `validateMidnightTakeFeasibility(...)`, called by the `MorphoMidnight` take flows, which returns the offers unchanged or a filtered copy.
- **Math / share-price helpers** — helpers for vault share-price bounds use
  `MAX_SLIPPAGE_TOLERANCE`. Only the `computeMax*SharePrice` helpers cap at
  `MAX_ABSOLUTE_SHARE_PRICE`: capping relaxes an upper bound, so it is safe there, whereas capping a
  `computeMin*SharePrice` floor would *lower* it and weaken the guard for any vault or market whose
  share price grew past the cap. The high-level Blue write methods do not use these helpers or accept
  slippage inputs. `computeVaultMaxSharePrice` accrues vault snapshots for fixed-bundle price
  protection and `grossFromNetAssets` exactly inverts VaultBundlesV1 referral-fee deductions.
  `computeMinForceWithdrawSharePrice` bounds a Vault V2 force withdrawal's realized exit price; it
  takes the plan's withdrawn assets and share-burn upper bound rather than a market, because the
  force-deallocation penalty puts the realized price structurally below the vault share price.
- **Vault V2 exit planning** — `resolveVaultV2ForceWithdrawEligibility` returns a discriminated verdict on VaultExitBundlesV1's four force-withdraw preconditions; `computeVaultV2ForceWithdrawPlan` derives every amount (penalty-free leg, penalised leg, penalty bound, market coverage, `maxExitAssets`, penalty-leg count) from a `getData()` snapshot with zero extra RPC; `computeVaultV2ForceWithdrawSharesBurnt` upper-bounds the share burn and serves as the slippage bound's denominator; `computeVaultV2ForceWithdrawMinSharesBurnt` lower-bounds the measured burn for the fee-mint guard, independent of how the exit splits at inclusion; `computeVaultV2ForceWithdrawFeeSharesMinted` accounts for fee-recipient mints at an accrual timestamp. The coverage sum is deliberately order-independent — the contract's loop visits every market taking `min(available, remaining)`, and a drained market is removed from the adapter's list mid-loop. The penalty-leg count behind the slippage floor is, for the same reason, a worst-case ascending walk (the most markets the loop can touch) rather than a replay of the prefetched `marketIds` order: it feeds the share-burn *upper* bound, so replaying a snapshot order that diverges at inclusion would under-count legs and over-state the floor, false-reverting a valid distressed exit; the residual looseness is bounded (≤ `penaltyLegs − 1` asset-units) and absorbed by `slippageTolerance`. `previewVaultV2ForceWithdraw` is the frontend-facing wrapper: it returns `undefined` for an ineligible vault instead of throwing, which is why the throwing path lives in the entity. It separates the capacity clock (`timestamp`) from the fee-mint projection clock (`feeProjectionTimestamp`) so a fee-recipient quote can mirror the entity's deadline guard without inflating `maxExitAssets`; when `referralFeeRecipient` equals `userAddress`, its `netAssets` includes the self-paid referral fee.
- **Shared-liquidity** — Vault V2 planning and state transitions live on
  `VaultV2BlueReallocationData`, whose outputs are the only reallocation inputs accepted by
  high-level Blue writes. Read-only liquidity metrics live on the Vault V2 reallocation-data
  entity, not in this layer.
- **Metadata** — `addTransactionMetadata(tx, metadata)` appends hex-encoded analytics bytes to `tx.data`: an optional 4-byte unix timestamp followed by a 4-byte origin. For entity flows, configure `metadata.timestamp: true` in `morphoViemExtension` client options and pass a fresh `now` to each flow; `resolveTransactionMetadata` replaces `true` with the flow's reference timestamp. Only the device-clock fallback (`true` without a flow `now`) is deprecated. Direct action or `addTransactionMetadata` callers can pass a bigint per transaction (including `0n`); do not store a per-transaction block timestamp in long-lived client options. The timestamp is omitted when false or unset. Explicit bigint timestamps must be uint32 seconds; invalid values throw typed input errors, even for empty calldata. Callers gate on `metadata` being provided; otherwise the helper is a no-op when `tx.data` is empty.

## Constants

Internal `parseMidnightMaker.ts` guards check tree intent and maker, deployment, ratifier,
loan-token and callback relationships inside whole-params maker constructors; they return ordinary
values, not independent stage witnesses. Maker bundle parsing owns publication, cancellation and
funding snapshots without freezing trees; dynamic publication validation remains in the entity layer.

- `VAULT_DEPOSIT_MAX_DEADLINE_SECONDS` = seven days: `validateVaultDepositDeadline(deadline, { now })` rejects a longer forward-accrual window with `InputExceedsMaxError`. Vault V1/V2 deposit entities and plan preparers, and the shared V1-to-V2 migration quote, call this internal non-barrel validator before price math. Clock-free raw actions accept caller-supplied price bounds instead.

- `MAX_SLIPPAGE_TOLERANCE` = 10% (`WAD / 10`) — slippage-tolerance ceiling for surfaces that still
  expose share-price protection, notably vault deposits. It does not apply to high-level Blue
  writes.
- `MIDNIGHT_MAX_REFERRAL_FEE_PCT` = 10% (`WAD / 10n`): SDK referral-fee cap for Vault, Blue, and Midnight, inclusive. WAD-scaled fees above the cap but below WAD throw `MidnightReferralFeePctExceededError`; TransactionPlan intents reject fees above 1,000 basis points with `InputExceedsMaxError`. The periphery contracts only require `referralFeePct < WAD`.
- `DEFAULT_LLTV_BUFFER` = 0.5% (`WAD / 200`) — hardcoded for Blue borrow, collateral-withdraw, and migration legs and the Midnight flows (`takeBorrow`, `supplyCollateralTakeBorrow`, `takeRepayWithdrawCollateral`, `repayWithdrawCollateral`, `withdrawCollateral`, and `withdrawCollateralBatch`). Midnight `makeBorrow` and `supplyCollateralMakeBorrow` intentionally skip it because debt only appears when someone fills the offer.
