# evm-simulation Conventions

- Simulate EVM bundles only through `eth_simulateV1`. RPC failures, timeouts, unsupported configuration and execution reverts propagate as typed errors; never select another provider, retry execution, or return a successful result after failure. Give the sole execution the full `timeoutMs` budget (default 5000 ms) — one shared `AbortSignal` covers `eth_getBlock*`, the contract-code `eth_getCode` reads, quoted-asset metadata reads and `eth_simulateV1`. A caller-supplied `block` skips the block lookup; a simulation is one `eth_simulateV1` request plus one `eth_getCode` per distinct calldata target and the metadata reads its quotes or inputs need. A successful simulation sends no `eth_chainId` lookup and there is no post-simulation reorg check; every call inside `eth_simulateV1` (including preparations and state reads) carries the request's `chainId` as a hex quantity, so nodes that check it reject a wrong-chain endpoint. Only after an `RpcTransportError` from the block lookup, contract-code `eth_getCode` reads, metadata reads or `eth_simulateV1`; a `SlippageCheckUnavailableError` from quoted-asset resolution (a market or vault absent on the served chain) or a failed planned state read parsed by `executePlan`; or a `SimulationValidationError` from the contract-code check (a calldata target with no code on the served chain), does the pipeline probe `eth_chainId` once. Another chain turns the failure into the non-bypassable `InvalidChainIdError` (an honest wrong-chain endpoint often fails with "block / header not found").
- Keep the simulation pipeline staged as request parsing → single block resolution (skipped for a caller-supplied `block`) → calldata-target contract-code check → subject/asset metadata resolution → derivation-read, balance/position-read, assertion and execution planning → `eth_simulateV1` boundary (in-block reads and assertions → response parsing) → transfer derivation → balance/position and derivation-state decoding → `deriveQuote` and final merged-quote validation → slippage checks → retention assertion.
- Order in-block calls as every `before` state read → preparations → for each transaction in order: its `assertBefore` reads → transaction → its `assertAfter` reads → every `after` state read. Evaluate preparation failures first, then each transaction's before assertions, transaction result, and after assertions in that order.
- The boundary requires an endpoint supporting `eth_simulateV1` with per-call `from` and `traceTransfers`; no `stateOverrides` are used. There is no fallback backend.
- No balance inflation: `value` transfers are funded by the sender's real native balance. `validation: false` means gas is not charged, which is how gas is separated from economic effects. Monad (143) is the one exception: its nodes reject `false`, so it sends `true`, and its simulated block still charges no gas (base fee 0, fees default to 0). Monad also defaults the state block to `finalized`, because simulating at its non-final `latest` number runs on another parent.
- Block advancement is observed, not required: geth-style nodes report the simulated block as `stateBlockNumber + 1` while Anvil reports the pinned block itself. The boundary accepts exactly the pinned block or pinned+1; consumers must read `block.blockNumber`/`block.blockTimestamp` on the returned execution, never assume +1. A pinned+1 block must report the pinned hash as `parentHash` unless `ChainSimulationConfig.parentHashCheck` is `false`. It defaults to off on Stable (988), whose nodes report a non-matching simulated `parentHash`, and on elsewhere. Block number and timestamp checks always run; with `parentHashCheck` off nothing checks the state-block hash.
- The block gas limit and per-call gas limit are caller configuration (`blockOverrides.gasLimit`, `callGasLimit`), each sent only when set; never hardcode either for a chain in the SDK.
- Native slippage amounts come from net `traceTransfers` movements on user calls; no baseline `eth_getBalance` read is needed. `validation: false` excludes gas charges; `calls`/`txIdx` index user transactions only.
- Let `SimulationRevertedError` propagate; a revert belongs to the bundle, not the backend.
- Keep RPC I/O under `src/simulate/backends/` and outputs normalized to the internal `SimulationExecution` type. Colocated transport-boundary tests cover request/response shapes and failures; per-call values that fail normalization are rejected as `InvalidSimulationResponseError`; pinned Anvil forks prove sequential state, in-block assertions, real native funding, and standalone-bundle retention.
- Preview `authorizations` are converted from SDK requirements into ordered simulation preparation calls. Do not verify permission/nonce read-back or re-derive authorization policy; preparation and transaction reverts propagate. Preview success does not validate future signatures.
- `limits` is required: callers pass quote-only `SimulationLimits` or mixed/input `SimulationInputLimits` with a non-empty `operations` array, or the literal `"none"` — an omitted `limits` or empty `operations` is rejected; `"none"` is reserved for transactions no operation type covers (Merkl reward claims; Midnight actions without an operation type, including pure maker publications and cancel-only actions; and approval/authorization-only bundles) and runs no checks, leaving `verification.operations` empty. `limits.operations` contains caller-selected actions/subjects and the shared `SlippageLimits` quote and WAD-scaled percentage tolerance. No calldata decoding, inferred constraints, or implicit health-policy checks. In the quote form, every operation requires its applicable position side (`sharesMinted`/`sharesBurned`/`collateralSupplied`/`collateralWithdrawn`/`creditRedeemed`/`unitsSold`/`unitsBought` per the operation table: `creditRedeemed` on `midnightRedeem` and `midnightTakeWithdraw`, `unitsSold` on `midnightTakeBorrow`, `unitsBought` on `midnightTakeLend`), and `midnightSupplyBlueMakeLend` requires callback-position `sharesMinted` plus exact `assetsPaid`; Blue parking combined with collateral supplies is unsupported; payout operations also require `assetsReceived`. Each combined collateral operation additionally requires its cap on the other leg (`sharesMinted` for `blueSupplyCollateralBorrow`, `collateralWithdrawn` for `blueRepayWithdrawCollateral`) — an active leg on either side requires that leg's other side (`sharesMinted` above `1n` → `assetsReceived` on `blueSupplyCollateralBorrow`, `collateralWithdrawn` above `1n` → `assetsReceived` on `blueRepayWithdrawCollateral`, `assetsPaid` above `1n` → `collateralSupplied`/`sharesBurned` respectively). `assetsPaid` is required on pay-in operations (`blueSupply`, `blueSupplyCollateral`, `midnightSupplyCollateral`, `midnightSupplyBlueMakeLend`, `midnightTakeLend`, `blueRepay`, `vaultV1Deposit`, `vaultV2Deposit`) and unconditionally on both combined ops (`1n` on an inactive pay-in leg), as well as on active repayment legs of `midnightRepayWithdrawCollateral` and on `midnightTakeRepayWithdrawCollateral`. `blueRefinance` requires `sharesBurned` plus the target-market `sharesMinted` debt cap. On wNative loan markets, `midnightTakeLend`'s `assetsPaid` counts ETH sent plus the sender's net wNative change against the full cap. `midnightTakeWithdraw` also requires the sender's Midnight debt to stay unchanged across the bundle. `midnightRepayWithdrawCollateral` quotes `assetsPaid` when the repay leg is active (`debtRepaid` or `position.maxDebt`), `debtRepaid` as a minimum, and per-index `collateralWithdrawals`; its `MidnightDebtPositionBounds` `maxDebt` and `maxCollateral` are exact. It also requires the sender's Midnight credit to stay unchanged across the bundle, and without a `debtRepaid` quote the sender's debt must not increase. `midnightTakeRepayWithdrawCollateral` runs the same checks and always requires the repay leg. Zero quote amounts are rejected. An omitted `slippageTolerance` defaults to blue-sdk's `DEFAULT_SLIPPAGE_TOLERANCE`; a supplied one must be below 1e18. An operation may additionally carry a `sharePrice` bound on the realized assets-per-share rate of its priced quote pair (RAY-scaled `expected`, WAD-fraction `tolerance`), absolute `position` bounds on the subject's post-bundle Blue position (Blue operations), Midnight credit (`maxCredit` on `midnightRedeem`), or Midnight debt and collateral (`maxDebt`/`maxCollateral` on `midnightRepayWithdrawCollateral`), compared inclusively and not scaled by tolerance, and `positions` or `assetsReceived` on in-kind redeems (one of the two required — the delivered per-market supply shares or the idle wallet portion, both minimum-bound); `penalty: 0n` and zero deallocation or position bounds stay valid — zero-quote rejection applies only to the amount fields. Vault V2 force exits check the penalty and per-market deallocations only when quoted; refunds are not checked. Missing evidence for a quoted amount throws a typed error.
- For `midnightSupplyBlueMakeLend`, quote the full parked amount in exact `assetsPaid` and callback-position `sharesMinted`. For wNative loan tokens, measurement adds sender ETH sent to the net wNative balance change, so native funding needs no quote adjustment.
- `midnightSupplyCollateralTakeBorrow` requires `unitsSold` and payout `assetsReceived`, plus exact, non-empty `collateralSupplies` with unique indices. It uses one net wallet bound per `(token, account)`. The combined operation throws `SimulationValidationError` when its wallet bounds overlap another operation's wallet balance reads or wallet bounds, or when its Midnight collateral, credit, or debt reads overlap another operation's Midnight position reads.
- Read only token/account balances needed by quoted or derived sides or market/account position shares and collateral (decoding `collateral` for `position` bounds), Midnight credit through `updatePositionView`, debt through `debt(id, account)`, per-index Midnight collateral, and receiver `balanceOf` for each withdrawn collateral index, deduplicated across entries. Resolve underlying tokens for quoted or derived asset sides without an explicit asset. Pinned-block derivation helpers may call vault previews, Blue `accrueInterest` then market/position reads, and migration target accrued totals, supply, fee and virtual-share reads. These run in the before phase, ahead of preparations and user transactions; helpers never appear in public transactions, transfers or asset changes. The Blue accrual persists into user transactions, so their per-call logs omit that market's `AccrueInterest` and `gasUsed` excludes accrual; keep this documented. For the first `midnightSupplyCollateral` into an uncreated market, pass its struct via `market` or set `assetPaid` to the selected collateral token. `limits: "none"` means no slippage or derivation reads. Do not add general state reporting, factory discovery, or full vault entity fetching.
- `InputOperationLimit` derives expectations independently from typed inputs and pinned-block state, never action args or calldata. The required-quote rules above apply to the quote form (`OperationLimit`); inputs do not require a supplied quote. Revalidate required sides after merging derivations and explicit overrides. Direct amounts, borrow debt shares and vault withdrawal/migration source shares are exact; other converted sides are adverse-only without percentage tolerance. Assets-mode Blue withdrawal shares allow one share wei below the derived amount per earlier subject-market supply evidenced in simulated logs. Only explicitly quoted sides use `slippageTolerance`. Declare referral fees and absolute reallocation penalties explicitly; undeclared charges fail the derived checks.
- State-based bounds cover the named subject across the entire bundle. Never label these aggregate measurements with a transaction index. Reject cross-operation wallet-balance overlaps with `SimulationValidationError` during read planning if any overlapping operation uses typed inputs, including native tokens and vault shares. Callers must split the bundle or use quote-only limits with bundle-wide wallet quotes for every overlapping operation. Same-operation sides can share a balance; quote-only overlaps remain supported. Same-token combined legs net the sender wallet against the receiver, independently of the position account. Return the checked quote, quoted-side tolerance and input-based `fieldChecks`. Keep `SimulationLimits` and `CheckedOperationLimit` quote-only; accept mixed requests through `SimulationInputLimits` and return the additive checked input types. Inactive combined legs forbid debt-share growth or collateral loss even with quote overrides. Preparation, state-read, and assertion calls never receive a public `txIdx`.
- Typed-input asset overrides must match the canonical subject token; native aliases require registered wNative and measure ETH plus net wNative wallet changes. Aliases are field-local for distinct wallets; same-token combined legs sharing one sender/receiver wallet use a shared native net measurement if either side selects the alias. Quote-only overrides remain trusted. Typed single-leg Blue supply/withdraw forbid debt-share growth and collateral loss; borrow/repay forbid collateral and supply-share loss; collateral operations forbid debt-share growth and supply-share loss through separate position-delta guards, including with explicit quotes. Both combined Blue operations also forbid undeclared supply-share loss. Multi-operation input bundles that move these counter-sides adversely are rejected: use a supported combined operation or quote-only limits with explicit position bounds.
  Typed wNative wallet sides held by the sender automatically net ETH whenever the request sends native value, even without an alias. Keep the Blue guard table compiler-exhaustive over the Blue keys of `OperationInputs`.
- Enforce retention by net `(restricted address, token)` balance across the blue-sdk `bundles` registry plus `midnightBundlesV2` with `DUST_THRESHOLD = 100n`; skip only chains that catalog neither.
- Keep thrown domain errors under `SimulationPackageError`; wrap RPC failures with `RpcTransportError` where the request is made, preserving their original cause, and wrap any other unexpected failure (including local viem errors) with `UnexpectedSimulationError` at the public simulation boundary. Services requiring simulation must block transaction return on every rejection. Use `toSimulationErrorResponse` for public failure fields and log original exceptions server-side.
- Assertions are caller-supplied `{ to, data, check }` calls. The check returns a failure message or `undefined`; built-in `erc20BalanceAssertion`, `nativeBalanceAssertion`, and `maxDepositAssertion` helpers accept inclusive `min`/`max` bounds (at least one is required). Amounts use token base units, wei, or vault asset units. Assertion calls run as ordinary calls and must be view calls; writes are visible to later calls. Morpho Vault V2 `maxDeposit` is `pure` and always returns 0, so a positive minimum is meaningful only for Vault V1/MetaMorpho.
- A custom assertion encodes its own read and interprets the raw return data, for example requiring an allowance to be zero:
  ```ts
  {
    to: USDC,
    data: encodeFunctionData({ abi: erc20Abi, functionName: "allowance", args: [owner, spender] }),
    check: (returnData) => hexToBigInt(returnData) === 0n ? undefined : "Allowance is not zero.",
  }
  ```
- `SimulationAssertError` identifies the caller transaction, phase and assertion index, a copy of the caller's assertion (`to`, `data`, and `check`), and raw return data (or revert data for a reverted read). Its JSON-safe response contains only the code, message, and transaction index.
- Add chains through caller `SimulationConfig.chains`; every per-chain `ChainSimulationConfig` requires `simulateV1Url`. Confirm blue-sdk `bundles` addresses intentionally.
- Keep unit tests colocated as `{module}.test.ts`; put shared unit fixtures in `src/test-helpers/`, which must stay out of published builds. Keep fork tests under `test/` as `*.integration.test.ts`.

## Continuous Improvement

- Keep backend I/O isolated behind normalized execution results; public simulation behavior should not depend on hidden backend state.
- Existing code may predate current conventions; do not widen divergence when touching it.
- Prefer typed failures and explicit backend support rules over broad catch/fallback logic.
- If a convention cannot yet be met, keep the exception local and make the touched surface closer to the target design.

- `@morpho-org/morpho-sdk` is a direct runtime dependency of this package, used through its root entry point for the requirements adapter and its `/abis` subpath for Morpho ABIs, and its `/midnight/utils` subpath to validate and normalize supplied Midnight market structs. Address lookups come from `@morpho-org/blue-sdk`. Every morpho-sdk bump requires the root AGENTS.md §7 dependent package bump audit for evm-simulation.
