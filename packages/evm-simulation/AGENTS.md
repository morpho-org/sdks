# evm-simulation Conventions

- Simulate EVM bundles only through `eth_simulateV1`. RPC failures, timeouts, unsupported configuration and execution reverts are typed errors that `simulate` reports in an `ok: false` report; the SDK never selects another provider, retries execution, or returns an `ok` report after failure. Every RPC call runs on a copy of the caller's viem client with CCIP-Read off, whatever the caller's `ccipRead` setting, so an `OffchainLookup` revert cannot fetch a gateway URL (`client.chain` required; the caller's client is not changed). `options.timeoutMs` (default 5000) is the one whole-simulation deadline: no read starts after it and a pending step fails as `RpcTransportError`, but a request already sent is not aborted. The SDK sets no retry policy; the caller's transport owns retries and endpoints, and a retrying or `fallback()` transport is documented as not recommended, not rejected. A caller-supplied `block` is verified with one `eth_getBlockByHash` before code or asset reads; mismatched number, hash or timestamp fails as `InvalidSimulationResponseError`, and a missing hash fails as `RpcTransportError`; a simulation is one `eth_simulateV1` request plus one `eth_getCode` per distinct calldata target without a code override, an additional delegate read for EIP-7702 targets without overridden delegate code, and the metadata reads its quotes or inputs need. A successful simulation sends no `eth_chainId` lookup and there is no post-simulation reorg check; every call inside `eth_simulateV1` (including preparations and state reads) carries `client.chain.id` as a hex quantity, so nodes that check it reject a wrong-chain endpoint as an `RpcTransportError`.
- Keep the simulation pipeline staged as request parsing → single block resolution (hash verification for a caller-supplied `block`) → concurrent calldata-target contract-code check and subject/asset and approval-token resolution at that block (code failures take precedence and end the run without waiting for assets) → pending-authorization check → derivation-read, balance/position-read, assertion and execution planning → `eth_simulateV1` boundary (in-block reads and assertions, including refinance market-parameter reads → response parsing → call-outcome checks: preparation reverts, per-transaction assertions and reverts, state-read failures) → whole-bundle approval-event check → effect check → effects-only control-call check → preparation transfer check → final-mode signed-authorization use check → transfer derivation → sender-outflow check → undeclared owner-position-change check → balance/position and derivation-state decoding → `deriveQuote` and final merged-quote validation → slippage checks → retention assertion → collect, then report every failure flat in pipeline order (no primary error, no findings). Reverts are terminal: the report keeps the preceding assertion failures, then the revert. A pre-execution failure ends the run and is reported alone.
- Immediately after transfer derivation, check undeclared sender outflows before slippage failures: operation-derived spend tokens only, excluding explicit approvals, zero-pull Blue borrow/collateral-withdrawal approvals, and the loan token on withdrawal-only `midnightRepayWithdrawCollateral`. Resolve existing vault and market tokens at the pinned block. The approval resolver's declared `midnightSupplyBlueMakeLend.loanToken` subject and first-market collateral `assetPaid` fallback without a validated `market` struct also permit spending; document that the fallback is not independently verified collateral. Source vault shares are spendable on exits and migration independently of registry bundlers. Registered wNative spend tokens allow native ETH only when that same active pay-in operation measures sender ETH, with wallet-bound native funding limited to gross traced sender ETH debits up to the native value already charged to the bound; incoming ETH and refunds do not offset extra debits. Detect net losses (including burns) and any positive outgoing transfer to another non-zero address, even if returned later, as `UnexpectedTokenTransferError` findings. Safety checks stay fatal except for the scoped [sender-outflow](../../docs/EXCEPTIONS.md#evm-simulation-non-blocking-sender-outflow-findings) and [owner-position-change](../../docs/EXCEPTIONS.md#evm-simulation-non-blocking-owner-position-change-findings) reporting exceptions. Undeclared sender outflows detected by this check are non-blocking warnings, never entries in `failures`. Convert them to recursively frozen plain `SimulationWarning` data with severity `"warn"` and code, token, sender, recipients and chainId context. Both report variants always carry a frozen `warnings` array, including when empty; the SDK performs no logging. `simulate` returns `ok: true` when nothing else fails; all other failures remain blocking. Integrators gating signing must inspect report warnings, even when `ok` is true. Signing services, including the Actions API attestor, must reject non-empty `report.warnings` before release under that exception. Verified chain-scoped paired emitters are ignored by the sender-outflow check whenever their listed primary token is spendable on that chain, producing no warning. Do not require primary transfer evidence or match txIdx, sender, recipient, amounts or event counts; no pair has an amount bound. Keep primary checks and reported transfers unchanged. Paired emitters on another chain or without a spendable primary retain the normal sender-outflow check. Ignore incoming, self and zero transfers. Preparation transfers already fail separately; these checks cover transactions and preparations, not assertion calls, which must be view calls. Native evidence excludes gas. `limits: "none"` retains the opt-out for funded consumer review bundles and provides no sender-outflow protection.
- Under the owner-position-change exception, report undeclared owner position changes, undecodable matching protocol logs and unusable refinance market-parameter reads (failed, undecodable, or a non-zero tuple for another market; `event: "MarketParams"`) as non-blocking `UNEXPECTED_POSITION_CHANGE` warnings with protocol, event, owner, optional marketId and chainId context. These warnings alone do not change `ok`. Signing integrators must inspect `report.warnings` even when `ok` is true.
- Combined Blue spendability requires an active pay-in leg: `blueSupplyCollateralBorrow` uses typed `inputs.collateralAssets` or quote-only positive `collateralSupplied`; `blueRepayWithdrawCollateral` uses typed `inputs.repay` (including `"full"`) or quote-only `sharesBurned`. The inactive `assetsPaid: 1n` cap and the unchanged approval allowlist do not authorize spending.
- Order in-block calls as every `before` state read → preparations → for each transaction in order: its `assertBefore` reads → transaction → its `assertAfter` reads → every `after` state read. Evaluate preparation failures first, then each transaction's before assertions, transaction result and revert check, its `assertLogs` checks on a frozen lowercase copy of that call's logs, and after assertions in that order.
- Require `eth_simulateV1` with per-call `from` and `traceTransfers`; no fallback backend.
  Copy caller-provided RPC-shaped `stateOverrides` and forward them unchanged,
  once before all calls in the single simulated block. Consumers validate them.
- Run all configured approval, signed-use, assertion, slippage and retention checks
  even with overrides. Their evidence describes the selected hypothetical state,
  not unmodified chain state or broadcast safety. See the
  [override trust boundary](./README.md#caller-provided-state-overrides).
  Explicit code overrides govern target-code checks, matched case-insensitively;
  metadata reads outside `eth_simulateV1` remain pinned to onchain state.
- Never add state overrides or inflate balances automatically. Without caller
  overrides, `value` transfers must use the sender's real native balance.
- `validation: false` means gas is not charged, which is how gas is separated from economic effects. Monad (143) is the one exception: its nodes reject `false`, so it sends `true`, and its simulated block still charges no gas (base fee 0, fees default to 0). Monad also defaults the state block to `finalized`, because its non-final `latest` block can be replaced and its pinned hash rejected.
- Select `eth_simulateV1` state with EIP-1898 `{ blockHash, requireCanonical: true }`, including Stable, Monad, HyperEVM and Anvil; reject selector errors as typed RPC failures without number fallback or additional RPC lookups. The flag requests rejection of retained non-canonical blocks. Probes on 2026-11-19 accepted it on all 22 live dev-eRPC chains serving the method and local Anvil; enforcement against a retained non-canonical block was not demonstrated. The seven chains without `eth_simulateV1` remain unverified (see the README compatibility table). Pinned metadata and code reads use the same hash with requireCanonical: true.
- Block advancement is observed, not required: geth-style nodes report the simulated block as `stateBlockNumber + 1` while Anvil reports the pinned block itself. The boundary accepts exactly the pinned block or pinned+1; consumers must read `block.blockNumber`/`block.blockTimestamp` on the returned execution, never assume +1. A pinned+1 block must report the pinned hash as `parentHash` unless `options.parentHashCheck` is `false`. It defaults to off on Stable (988), whose nodes report a non-matching simulated `parentHash`, and on elsewhere. Block number and timestamp checks always run, independently of hash selection.
- The block gas limit and per-call gas limit for user transactions, preparations and assertions are caller configuration (`blockOverrides.gasLimit`, `callGasLimit`), sent only when set. Read-only calls the SDK inserts to gather evidence may carry a documented, fixed, chain-independent SDK gas limit, split from a fixed total for all such reads, capped at half the pinned block's gas limit, because reth-style nodes reject a block whose explicit call gas exceeds its gas limit (HyperEVM small blocks: 3M); when the total cannot give each read a documented per-read floor, the SDK sends no limit on its reads, so the node default applies. `callGasLimit` overrides it, and the SDK omits its own limit when `blockOverrides.gasLimit` is set so tight block limits keep node-default behavior. Nodes such as Monad reserve a large default per call when `gas` is omitted, so SDK-added reads would otherwise reduce the number of user transactions that fit. Every other simulated call, including SDK-inserted calls that change state such as Blue `accrueInterest`, uses caller configuration only.
- Native slippage amounts come from net `traceTransfers` movements on user calls; no baseline `eth_getBalance` read is needed. Blue collateral `assetsPaid` (`blueSupplyCollateral` / `blueSupplyCollateralBorrow`, including native-ETH quotes) uses the larger of the net debit and gross owner outflows, except derived same-token net pay-ins. Native-sentinel quotes on registered wNative add only net wrapped debits (`wrappedDebitOnly`); credits cannot lower payment. Combined gross funding counts ETH and wNative owner outflows, offsetting burns/wraps only against matching conversion receipts. Any operation's proceeds read of that wNative balance forces ETH-only payment; another operation's funding bound can cover it instead, but native collateral combined-payment reads do not cover one another. ETH-only fallbacks retain gross ETH caps. `validation: false` excludes gas charges; `calls`/`txIdx` index user transactions only.
- A transaction revert ends evaluation: `evaluateCalls` returns `reverted` with the earlier assertion failures and the `SimulationRevertedError`, and the pipeline reports them without running later checks. A preparation revert or a bundle-level revert still throws and is reported alone; a revert belongs to the bundle, not the backend.
- Keep RPC I/O under `src/simulate/backends/` and outputs normalized to the internal `SimulationExecution` type. Colocated transport-boundary tests cover request/response shapes and failures; per-call values that fail normalization are rejected as `InvalidSimulationResponseError`; pinned Anvil forks prove sequential state, in-block assertions, real native funding, and standalone-bundle retention.
- Preview `authorizations` are converted from SDK requirements into ordered simulation preparation calls. Preparations with ERC-20 Transfer or WETH Deposit/Withdrawal event signatures (including malformed and four-topic logs) fail closed with `SimulationValidationError`; native-value trace transfers are also rejected because they carry the ERC-20 Transfer topic. Callers must simulate those authorizations as transactions in final mode to check their flows. Tokens emitting no logs remain outside this check. Before `eth_simulateV1`, check every pending token approval, ERC-2612 permit, Permit2 transfer signature, Morpho authorization, and EcrecoverAuthorizer signature against the operation-derived plus explicit approval allowlist. Midnight pay-in approval tokens come from the pinned Midnight market (Blue parking: its declared `loanToken`), never from quote overrides, except an explicit `assetPaid` on a first `midnightSupplyCollateral` or `midnightSupplyCollateralMakeBorrow` into a market the bundle creates. Whole-bundle approval-event checks include preparation and user calls. Do not verify permission/nonce read-back; preparation and transaction reverts are reported as `SimulationRevertedError`. Preview success does not validate future signatures.
- `limits` is required: callers pass quote-only `SimulationLimits` or mixed/input `SimulationInputLimits` with a non-empty `operations` array or non-empty validated `effects`, or the literal `"none"` — an omitted `limits` or empty `operations` without non-empty validated `effects` is rejected; `"none"` is reserved for transactions no operation type covers (Merkl reward claims; Midnight actions without an operation type, including pure maker publications and cancel-only bundles) and opts out of limits and approval-allowlist checks, but final-mode signed-authorization use checks still run, leaving `verification.operations` empty. `limits.approvals` adds caller-approved token, Morpho authorization, or Midnight authorization entries to the operation-derived set; Midnight `SetIsAuthorized` grants are checked from the registered Midnight emitter. Derive approvals only from the declared operation type/subject, simulation owner, resolved subject token, and chain registry; never infer permissions from calldata or caller token overrides, except an explicit `assetPaid` on a first `midnightSupplyCollateral` or `midnightSupplyCollateralMakeBorrow` into a market the bundle creates. Amounts are not bounded. `limits.operations` contains caller-selected actions/subjects and the shared `SlippageLimits` quote and WAD-scaled percentage tolerance. No calldata-derived permissions, inferred economic constraints, or implicit health-policy checks. Effects-only requests additionally restrict bound calldata to declared control calls as described below. In the quote form, every operation requires its applicable position side (`sharesMinted`/`sharesBurned`/`collateralSupplied`/`collateralWithdrawn`/`creditRedeemed`/`unitsSold`/`unitsBought` per the operation table: `creditRedeemed` on `midnightRedeem` and `midnightTakeWithdraw`, `unitsSold` on `midnightTakeBorrow`, `unitsBought` on `midnightTakeLend`), and `midnightSupplyBlueMakeLend` requires callback-position `sharesMinted` plus exact `assetsPaid`; Blue parking combined with collateral supplies is unsupported; payout operations also require `assetsReceived`. Each combined collateral operation additionally requires its cap on the other leg (`sharesMinted` for `blueSupplyCollateralBorrow`, `collateralWithdrawn` for `blueRepayWithdrawCollateral`) — an active leg on either side requires that leg's other side (`sharesMinted` above `1n` → `assetsReceived` on `blueSupplyCollateralBorrow`, `collateralWithdrawn` above `1n` → `assetsReceived` on `blueRepayWithdrawCollateral`, `assetsPaid` above `1n` → `collateralSupplied`/`sharesBurned` respectively). `assetsPaid` is required on pay-in operations (`blueSupply`, `blueSupplyCollateral`, `midnightSupplyCollateral`, `midnightSupplyCollateralMakeBorrow`, `midnightSupplyBlueMakeLend`, `midnightTakeLend`, `blueRepay`, `vaultV1Deposit`, `vaultV2Deposit`) and unconditionally on both combined ops (`1n` on an inactive pay-in leg), as well as on active repayment legs of `midnightRepayWithdrawCollateral` and on `midnightTakeRepayWithdrawCollateral`. `blueRefinance` requires `sharesBurned` plus the target-market `sharesMinted` debt cap. On wNative loan markets, `midnightTakeLend`'s `assetsPaid` counts ETH sent plus the sender's net wNative change against the full cap. `midnightTakeWithdraw` also requires the sender's Midnight debt to stay unchanged across the bundle. `midnightRepayWithdrawCollateral` quotes `assetsPaid` when the repay leg is active (`debtRepaid` or `position.maxDebt`), `debtRepaid` as a minimum, and per-index `collateralWithdrawals`; its `MidnightDebtPositionBounds` `maxDebt` and `maxCollateral` are exact. It also requires the sender's Midnight credit to stay unchanged across the bundle, and without a `debtRepaid` quote the sender's debt must not increase. `midnightTakeRepayWithdrawCollateral` runs the same checks and always requires the repay leg. Zero quote amounts are rejected. An omitted `slippageTolerance` defaults to blue-sdk's `DEFAULT_SLIPPAGE_TOLERANCE`; a supplied one must be below 1e18. An operation may additionally carry a `sharePrice` bound on the realized assets-per-share rate of its priced quote pair (RAY-scaled `expected`, WAD-fraction `tolerance`), absolute `position` bounds on the subject's post-bundle Blue position (Blue operations), Midnight credit (`maxCredit` on `midnightRedeem`), or Midnight debt and collateral (`maxDebt`/`maxCollateral` on `midnightRepayWithdrawCollateral`), compared inclusively and not scaled by tolerance, and `positions` or `assetsReceived` on in-kind redeems (one of the two required — the delivered per-market supply shares or the idle wallet portion, both minimum-bound); `penalty: 0n` and zero deallocation or position bounds stay valid — zero-quote rejection applies only to the amount fields. Vault V2 force exits check the penalty and per-market deallocations only when quoted; refunds are not checked. Missing evidence for a quoted amount throws a typed error.
- Exact control `effects` cover ERC-20 approvals, Blue/Midnight authorizations and direct Midnight cancellations. Omitted `txIdx` binds to the last caller transaction, excluding preparations; explicit indices must be in range. Match the last registered-emitter event per permission pair or cancellation group (including zero approvals/revocations and each cancelled group at maxUint128), block positive sender outflow in that transaction, and scope each implicit granting permission pair to that transaction. Zero approvals/revocations never implicitly allow grants. Fail with `SimulationEffectError`; these blocking checks do not change existing outflow warnings or explicit grant allowlists.
- When `operations: []`, require at least one effect resolving to every caller transaction (not preparations), then restrict each caller transaction's target and calldata to its declared control calls: token `approve`, registered Blue `setAuthorization`/`setAuthorizationWithSig`, registered Midnight `setIsAuthorized`/`setConsumed` or one SDK `multicall` whose subcalls all match declared effects. Reject economic or nested multicall subcalls, mismatched arguments and native value with `SimulationEffectError`; SDK trailing analytics metadata remains accepted. This is a restriction, not permission or economic-limit inference from calldata. Non-empty operation limits remain bundle-wide. Caller requirement transactions need their own indexed effects or must be simulated separately; never exempt unbound caller transactions.
- For `midnightSupplyBlueMakeLend`, quote the full parked amount in exact `assetsPaid` and callback-position `sharesMinted`. For wNative loan tokens, measurement adds sender ETH sent to the net wNative balance change, so native funding needs no quote adjustment.
- For `midnightSupplyCollateral` and `midnightSupplyCollateralMakeBorrow`, wNative collateral checks count ETH sent plus the sender's net wNative change against `assetsPaid`; sending value with no measured native side fails with `SimulationValidationError`, while a chain without registered wNative fails with `SlippageCheckUnavailableError`.
- `midnightSupplyCollateralBatch` requires exact, non-empty `collateralSupplies` with unique indices: one `midnightCollateral` measurement per index, exact minimum collateral credit, and wallet pull caps summed per token. Approval limits target Midnight once per distinct collateral token. The helper requires encoded `args.onBehalf` to equal `owner`; `options.onBehalf` must equal `owner` or be omitted. Exact supplies cannot be overridden through `expected`.
- `midnightWithdrawCollateralBatch` requires non-empty `collateralWithdrawals` with unique indices: one `midnightCollateral` measurement per index and receiver balance reads deduplicated per token. Position decreases are capped per index; receiver delivery minimums sum the quoted withdrawals per token, with slippage tolerance. The helper binds `options.receiver ?? owner` to `args.receiver`, allowing a non-owner receiver. Execution reverts propagate as `SimulationRevertedError`.
- `midnightSupplyCollateralTakeBorrow` requires `unitsSold` and payout `assetsReceived`, plus exact, non-empty `collateralSupplies` with unique indices. It uses one net wallet bound per `(token, account)`. The combined operation fails with `SimulationValidationError` when its wallet bounds overlap another operation's wallet balance reads or wallet bounds, or when its Midnight collateral, credit, or debt reads overlap another operation's Midnight position reads.
- A non-zero-root maker collateral supply uses quote-only `midnightSupplyCollateralMakeBorrow` with `assetsPaid` and `collateralSupplied` quotes and permits ratifier grants; direct `midnightSupplyCollateral` does not. The first-market `assetPaid` fallback applies to both collateral limit types.
- Read only token/account balances needed by quoted or derived sides or market/account position shares and collateral (decoding `collateral` for `position` bounds), Midnight credit through `updatePositionView`, debt through `debt(id, account)`, per-index Midnight collateral, receiver `balanceOf` for each withdrawn collateral index, and source/target Blue market parameters for owner-account `blueRefinance` matching, deduplicated across entries. Resolve approval tokens from the operation subject at the pinned block even when quote assets are overridden; fail closed when required tokens or registry addresses are unavailable. Resolve underlying tokens for quoted or derived asset sides without an explicit asset. Pinned-block derivation helpers may call vault previews, Blue `accrueInterest` then market/position reads, and migration target accrued totals, supply, fee and virtual-share reads. These run in the before phase, ahead of preparations and user transactions; refinance market-parameter reads run only in the after phase so markets created in the bundle can be observed. Helpers never appear in public transactions, transfers or asset changes. The Blue accrual persists into user transactions, so their per-call logs omit that market's `AccrueInterest` and `gasUsed` excludes accrual; keep this documented. For the first `midnightSupplyCollateral` or `midnightSupplyCollateralMakeBorrow` into an uncreated market, pass its struct via `market` or set `assetPaid` to the selected collateral token. `limits: "none"` means no slippage or derivation reads. Do not add general state reporting, factory discovery, or full vault entity fetching.
- `InputOperationLimit` derives expectations independently from typed inputs and pinned-block state, never action args or calldata. The required-quote rules above apply to the quote form (`OperationLimit`); inputs do not require a supplied quote. Revalidate required sides after merging derivations and explicit overrides. Direct amounts, borrow debt shares and vault withdrawal/migration source shares are exact; other converted sides are adverse-only without percentage tolerance. For typed-input vault limits, shares minted to the measured account during the bundle (vault fee accrual) are added back to the observed burn, and any outgoing vault-share transfer from that account to another non-zero address rejects the limit; quote-only bounds keep the net balance change. Assets-mode Blue withdrawal shares allow one share wei below the derived amount per earlier subject-market supply evidenced in simulated logs. Only explicitly quoted sides use `slippageTolerance`. Declare referral fees and absolute reallocation penalties explicitly; undeclared charges fail the derived checks.
- State-based bounds cover the named subject across the entire bundle. Never label these aggregate measurements with a transaction index. Reject cross-operation wallet-balance overlaps with `SimulationValidationError` during read planning if any overlapping operation uses typed inputs, including native tokens and vault shares. Callers must split the bundle or use quote-only limits with bundle-wide wallet quotes for every overlapping operation. Same-operation sides can share a balance; quote-only overlaps remain supported. Same-token combined legs net the sender wallet against the receiver, independently of the position account. Return the checked quote, quoted-side tolerance and input-based `fieldChecks`. Keep `SimulationLimits` and `CheckedOperationLimit` quote-only; accept mixed requests through `SimulationInputLimits` and return the additive checked input types. Inactive combined legs forbid debt-share growth or collateral loss even with quote overrides. Preparation, state-read, and assertion calls never receive a public `txIdx`.
- Typed-input asset overrides must match the canonical subject token; native aliases require registered wNative and measure ETH plus net wNative wallet changes. Aliases are field-local for distinct wallets; same-token combined legs sharing one sender/receiver wallet use a shared native net measurement if either side selects the alias. Quote-only overrides remain trusted. Typed single-leg Blue supply/withdraw forbid debt-share growth and collateral loss; borrow/repay forbid collateral and supply-share loss; collateral operations forbid debt-share growth and supply-share loss through separate position-delta guards, including with explicit quotes. Both combined Blue operations also forbid undeclared supply-share loss. Multi-operation input bundles that move these counter-sides adversely are rejected: use a supported combined operation or quote-only limits with explicit position bounds.
  Typed wNative wallet sides held by the sender automatically net ETH whenever the request sends native value, even without an alias. Keep the Blue guard table compiler-exhaustive over the Blue keys of `OperationInputs`.
- Enforce retention by net `(restricted address, token)` balance across the blue-sdk `bundles` registry plus `midnightBundlesV2` with `DUST_THRESHOLD = 100n`; skip only chains that catalog neither. Back the log-derived flow with state: for every ERC-20 token the operations measure, read each restricted intermediary's `balanceOf` before and after the bundle in the same `eth_simulateV1` block, and fail when it grows above dust even if the logs net to zero. This state check also runs when a `MALFORMED_TRANSFER_LOG` discarded transfer evidence. Include report-level `verification.retention` (`"checked"` or `"skipped-unsupported-chain"`) whenever retention runs with complete user-transaction logs, complete retention balance reads and no discarded transfer records, even on failed reports; omit `verification` for any `MALFORMED_TRANSFER_LOG` warning, missing user-transaction logs (unlike explicit empty `logs: []`), a planned retention `balanceOf` read missing or undecodable before or after the bundle, early failures, reverts or unusable transfer evidence. Preserve warnings and blocking findings from remaining evidence. Report skipped checks and pre-existing-balance sweeps as typed warnings. Accept the deprecated `options.logger` for compatibility but never invoke it. Keep it and the exported deprecated `SimulationLogger` through at least one coexistence minor before removal in a future major; direct consumers to `report.warnings`.
- Keep domain errors under `SimulationPackageError`; `simulate` returns them in its report and throws only `UnexpectedSimulationError`; wrap RPC failures with `RpcTransportError` where the request is made, preserving their original cause, and wrap any other unexpected failure (including local viem errors) with `UnexpectedSimulationError` at the public simulation boundary. Services requiring simulation must return transactions only from an `ok` report. Map each of `report.failures` with `toSimulationErrorResponse` for public failure fields and log original errors server-side. `toSimulationLimits` still throws its typed errors.
- Assertions are caller-supplied `{ to, data, check }` calls. The check returns a failure message or `undefined`; built-in `erc20BalanceAssertion`, `nativeBalanceAssertion`, and `maxDepositAssertion` helpers accept inclusive `min`/`max` bounds (at least one is required). Amounts use token base units, wei, or vault asset units. Assertion calls run as ordinary calls from the owner and must be view calls; writes act with the owner's authority and are visible to later calls. Morpho Vault V2 `maxDeposit` is `pure` and always returns 0, so a positive minimum is meaningful only for Vault V1/MetaMorpho.
- Each transaction may also declare `assertLogs` as `{ check }` callbacks. All checks for that transaction receive the same recursively frozen copy of only its logs in emission order, including synthetic native-transfer logs under viem's `ethAddress`; `address`, `topics`, and `data` are lowercase hex. It adds no planned call. A returned failure or thrown check error is reported as `SimulationLogAssertError` with code `SIMULATION_ASSERT_FAILED`, transaction and assertion indexes, a copy of the assertion, the lowercase logs, and a thrown error as `cause`.
- A custom assertion encodes its own read and interprets the raw return data, for example requiring an allowance to be zero:
  ```ts
  {
    to: USDC,
    data: encodeFunctionData({ abi: erc20Abi, functionName: "allowance", args: [owner, spender] }),
    check: (returnData) => hexToBigInt(returnData) === 0n ? undefined : "Allowance is not zero.",
  }
  ```
- `SimulationAssertError` identifies the caller transaction, phase and assertion index, a copy of the caller's assertion (`to`, `data`, and `check`), and raw return data (or revert data for a reverted read). Its JSON-safe response contains only the code, message, and transaction index.
- `SimulationLogAssertError` identifies the caller transaction and log-assertion index, a copy of the caller's `{ check }` assertion, and the lowercase log values passed to the check. The check receives those values in a frozen copy. It reuses `SIMULATION_ASSERT_FAILED`; its JSON-safe response contains only the code, message, and transaction index.
- Chains come from the caller's client (`client.chain.id`); never probe `eth_chainId` or build a client in the SDK. Confirm blue-sdk `bundles` addresses intentionally.
- Adding or changing a chain's `wNative` requires checking receipts from recent, known wraps and unwraps. Add the chain and its wrapper address to `NO_WNATIVE_MIRROR_WRAPPERS` only if wraps emit `Deposit` and unwraps emit `Withdrawal` without matching zero-address `Transfer` events. Remove the entry if the wrapper starts mirroring (the signal is `WRAPPED_NATIVE_MIRROR_DETECTED` in `report.warnings`; it reaches monitoring only if consumers forward report warnings). If wraps and unwraps emit only a zero-address `Transfer` and no `Deposit` or `Withdrawal`, add the chain and wrapper to `TRANSFER_ONLY_WNATIVE_WRAPPERS` instead. The transfer counts as the mint or burn without a `WRAPPED_NATIVE_DEDUP_MISS` warning. A chain belongs in at most one list. Unlisted chains keep one-to-one dedup.
- Keep unit tests colocated as `{module}.test.ts`; put shared unit fixtures in `src/test-helpers/`, which must stay out of published builds. Keep fork tests under `test/` as `*.integration.test.ts`.
- Both standalone SDK actions (`midnightSupplyCollateral` and `midnightSupplyCollateralWithNative`) emit the `midnightSupplyCollateral` operation. Only the direct action allows a different beneficiary; the native action checks `args.accountAddress` against `owner`.
- Branch CI runs direct, full-native, and partial-native standalone collateral cases on Ethereum, Base, and Arbitrum. In the action matrix, branch CI runs the EOA with the first non-wNative loan asset; other actor/asset variants are nightly. Robinhood is outside the branch chain matrix and runs nightly.

## Continuous Improvement

- Keep backend I/O isolated behind normalized execution results; public simulation behavior should not depend on hidden backend state.
- Existing code may predate current conventions; do not widen divergence when touching it.
- Prefer typed failures and explicit backend support rules over broad catch/fallback logic.
