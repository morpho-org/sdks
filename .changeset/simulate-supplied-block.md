**This is a breaking release with no deprecation period** — the removed API is deleted outright, not marked `@deprecated` in a 5.x release. `simulate()` now takes the caller's viem client — `simulate(client, params)` — and the chain comes from `client.chain.id`. `SimulationConfig` and `ChainSimulationConfig` are removed: `SimulateParams.chainId` is gone, and `logger`, `timeoutMs`, `blockOverrides.gasLimit` and `parentHashCheck` moved onto `SimulateParams`. The client's transport owns the endpoint, its timeout and retries. `simulate()` no longer calls `eth_chainId` before simulating or re-fetches the state block after `eth_simulateV1` to check for a reorg. The new optional `block` parameter (`{ number, hash, timestamp }`, exported as `StateBlock`) skips the block lookup, so a simulation without quoted-asset metadata reads sends only `eth_simulateV1`. `block` cannot be combined with `blockNumber`. Every call inside `eth_simulateV1` carries `client.chain.id`, so nodes that check it reject an endpoint on another chain with the new `InvalidChainIdError` without an extra RPC request; failures before `eth_simulateV1` (block lookup, metadata reads) still surface as `ExternalServiceError`. See `docs/migrations/evm-simulation-v5-to-v6.md`.
