Replace the legacy transfer-diff verification with the v5 authorization and effect verification pipeline. `simulate` now returns `Promise<VerifiedSimulationResult>`: the request is parsed, effective limits are resolved, and a single `eth_simulateV1` executes the user's transactions together with in-block state reads at the before and after phases of the simulated block — with one `AbortSignal` spanning every RPC.

State reads are plain view calls interleaved in the block (`balanceOf`, `allowance`, ERC-2612 `nonces`, Permit2 `nonceBitmap`, Morpho `market`/`position`/`isAuthorized`/`nonce`, oracle prices, IRM `rateAtTarget`, and per-vault totals/allocations for V1 and V2 vaults). They are parsed into the public `SimulationState` shape and diffed into signed `SimulationStateChange`s; markets are additionally accrued to the simulated block timestamp so every check compares like-for-like states.

Preview mode semantics: wallet requests (`erc20Approval`, `permit`, `permit2SignatureTransfer`) and Blue authority requests are *prepared* on-chain before the user transactions — approvals as owner `approve` calls, signatures as equivalent owner grants — and each request is verified against the observed state change (the approval exists, the nonce moved as expected, the permission was actually exercised by a pull). Each request is verified purely against the observed contract-state diff — allowance granted, nonce moved, `isAuthorized` set, permission exercised by a pull; a request that does not match the observed change throws `AuthorizationRequestMismatchError`, and a permission that does not match the expected post-state throws `PermissionChangeMismatchError`. `simulationTxs`, `calls`, and `transfers` expose user transactions only: state reads and preparation calls never appear in the public result.

Final mode performs a pure read-back: no authorizations may be supplied, and each signature form is checked against the before state (allowance coverage, ERC-2612 nonce and deadline, Permit2 bitmap and deadline, `isAuthorized` or earlier-op satisfaction, Blue nonce and deadline).

Every `limits.operations` entry is the caller-supplied description of one operation in the bundle, and gets exact effect verification against the before/after snapshots accrued to the simulated block timestamp: Blue supply/withdraw/collateral/borrow/repay legs checked with blue-sdk share math and LTV/LLTV-buffer bounds, refinances checked leg-by-leg (source closed to zero, target collateral moved exactly, dust bounded by `limits.maxSlippageWad`), vault deposits/withdrawals/redeems/migrations checked against preview mint/burn amounts, VaultExitBundlesV1 force exits checked per deallocation leg including `forceDeallocatePenalties`, and in-kind redemptions checked per market leg. When `limits.operations` is absent or empty no per-operation checks run; authorization preparation and retention checks still do.

Each `limits.operations` entry pins only what the caller declares: `expected*` equality fields plus `min*`/`max*` bounds such as `minSupplySharesMinted` are compared directly against the observed outcome, unpinned fields are unchecked, and violations throw `ConsumerLimitViolationError`. `expectedDeallocations` and `expectedMarketIds` are matched against the observed adapter/market deltas; `expectedFullClose` requires the residual share balance to be zero. New typed errors that can now fire from `simulate`: `MissingVerificationEvidenceError`, `PermissionChangeMismatchError`, `MarketConstraintViolationError`, `SlippageLimitExceededError`, `AssetChangeMismatchError`, `StateChangeMismatchError`, `ProtocolBindingMismatchError`, and `ConsumerLimitViolationError`. `UnsupportedVerificationFeatureError` remains exported but is no longer thrown by `simulate` — the preview-authorization and limits gates are removed.
