Replace the legacy transfer-diff verification with the v5 authorization and effect verification pipeline. `simulate` now returns `Promise<VerifiedSimulationResult>`: the request is parsed, effective limits are resolved, and a single `eth_simulateV1` executes the user's transactions together with in-block state reads at the before and after phases of the simulated block — with one `AbortSignal` spanning every RPC.

State reads are plain view calls interleaved in the block (`balanceOf`, `allowance`, ERC-2612 `nonces`, Permit2 `nonceBitmap`, Morpho `market`/`position`/`isAuthorized`/`nonce`, oracle prices, IRM `rateAtTarget`, and per-vault totals/allocations for V1 and V2 vaults). They are parsed into the public `SimulationState` shape and diffed into signed `SimulationStateChange`s; markets are additionally accrued to the simulated block timestamp so every check compares like-for-like states. In preview mode, pending authorizations are *prepared* on-chain before the user transactions — approvals as owner `approve` calls, signatures as equivalent owner grants — and each request is verified purely against the observed contract-state diff; in final mode each signature form is checked against the before state. `simulationTxs`, `calls`, and `transfers` expose user transactions only: state reads and preparation calls never appear in the public result.

`limits.operations` is the caller's description of what the bundle does: each entry names a subject (a Blue market, a vault, a refinance pair, a Morpho authorization) and pins only the fields the caller declares — `expected*` equality fields plus `min*`/`max*` bounds such as `minSupplySharesMinted`. The before/after state diff is checked per entry and only pinned fields are compared; anything unpinned is unchecked, and when `limits.operations` is absent or empty no per-operation checks run (authorization and retention checks still do). `expectedDeallocations` and `expectedMarketIds` are matched against observed adapter/market deltas; `expectedFullClose` requires the residual share balance to be zero.

Typed errors that can now fire from `simulate`: `AuthorizationRequestMismatchError`, `PermissionChangeMismatchError`, `MissingVerificationEvidenceError`, `InvalidSimulationResponseError`, `AssetChangeMismatchError`, `StateChangeMismatchError`, `MarketConstraintViolationError`, `UnsupportedOperationError`, `BlacklistViolationError`, and `ConsumerLimitViolationError` — plus the pre-existing `SimulationValidationError`, `SimulationRevertedError`, `UnsupportedChainError`, `ExternalServiceError`, and `UnexpectedSimulationError`.
